## 1. 环境清单

### 1.1 服务器（后端 + 前端）

| 项 | 最低 | 建议 |
|---|---|---|
| CPU | 2 核 | 4 核（LibreOffice 转换吃 CPU） |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 40 GB | 100 GB 数据盘（文件默认保留 7 天） |
| 系统 | Ubuntu 22.04 / 24.04 LTS | 同左；CentOS 需自行调整包名 |
| 软件 | JDK 17、MySQL 8、Nginx、LibreOffice、中文字体 | 一键脚本自动安装 |
| 网络 | 出网（调支付渠道）、入网 443（支付回调） | 域名 + 已备案 |

> 关键：**服务器必须能被支付宝/微信访问到 443 端口**，否则扫码后回调进不来，用户付了钱订单不会变。若无法开放公网，请让网络管理员把支付渠道回调地址映射进来。

### 1.2 打印电脑（跑打印助手）

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11（推荐）或 Linux + CUPS |
| 运行时 | .NET 8 Runtime（或使用 self-contained 发布包） |
| 打印组件 | SumatraPDF（Windows，**必须装**，否则份数/双面/彩色无法控制） |
| 打印机 | 已安装驱动，能正常打印测试页 |
| 网络 | 能访问后端 `http://服务器:8080` 或 `https://域名` |

### 1.3 账号与资质

| 项 | 说明 |
|---|---|
| 支付宝 | 企业账号 → 开通「当面付」（`alipay.trade.precreate`），拿到 APPID、应用私钥、支付宝公钥、商户 PID |
| 微信支付 | 商户号（mchid）+ 绑定 APPID → 开通 Native 支付，下载商户证书与平台证书，设置 APIv3 密钥 |
| 短信 | 阿里云或腾讯云短信，签名与模板需审核通过（验证码模板） |

## 2. 部署方式一：Docker Compose（推荐先跑通）

```bash
# 1. 取代码
git clone <仓库地址> print-system && cd print-system

# 2. 准备环境变量（至少改 5 项，见文件内【必改】标注）
cp .env.example .env
vi .env
#   PUBLIC_BASE_URL=https://print.your-domain.com
#   DB_PASSWORD=<强口令>
#   ADMIN_PASSWORD=<强口令>
#   AGENT_TOKEN=<openssl rand -hex 32 的输出>
#   PAY_MOCK_ENABLED=false

# 3. 启动（首次会构建镜像，含 LibreOffice，约 5~10 分钟）
docker compose up -d --build

# 4. 观察启动
docker compose logs -f backend
curl -k https://print.your-domain.com/health

# 5. 建表（compose 首次启动时已自动导入，仅重建数据卷后需要）
# docker compose exec -T mysql mysql -uroot -p"$DB_ROOT_PASSWORD" print_system < backend/schema-mysql.sql
```

TLS：compose 内 Nginx 监听 80，生产建议在其前面放云负载均衡/另一层 Nginx 终止 TLS，或用 certbot 容器。若只有单机，可直接用第 3 节的裸机方案（脚本已包含证书指引）。

## 3. 部署方式二：Ubuntu 裸机一键脚本

```bash
git clone <仓库地址> print-system && cd print-system

# 全量安装（装依赖 + 建库 + 编译 + 装服务 + 配 Nginx）
sudo bash deploy/install.sh

# 脚本会输出三个随机口令（数据库/管理员/助手密钥），务必立刻记录
```

脚本做的事：

1. 安装 JDK17、Maven、Node 20、LibreOffice、中文字体、MySQL、Nginx
2. 创建系统用户 `printsys` 与目录 `/opt/printsys/{backend,frontend,data,logs}`
3. 生成 `/opt/printsys/.env`（权限 600）
4. 编译后端 jar 与前端 dist 并发布
5. 建库导入 `schema-mysql.sql`
6. 安装 `printsys-backend.service`、`deploy/nginx.conf` 并启动
7. 轮询 `/api/health` 直到后端就绪

之后申请证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo sed -i 's/print.example.com/你的域名/g' /etc/nginx/conf.d/printsys.conf
sudo certbot --nginx -d 你的域名
sudo nginx -t && sudo systemctl reload nginx
```

重新发布（改了代码）：

```bash
cd print-system && git pull
sudo SKIP_APT=1 bash deploy/install.sh
```

## 4. 部署方式三：手工部署（了解每一步在做什么）

```bash
# ---- 后端 ----
sudo apt install -y openjdk-17-jre-headless maven libreoffice-writer libreoffice-calc \
                    libreoffice-impress fonts-noto-cjk fonts-wqy-zenhei nginx mysql-server
cd backend && mvn clean package -DskipTests
sudo mkdir -p /opt/printsys/{backend,data/uploads,logs}
sudo cp target/print-system-1.1.0.jar /opt/printsys/backend/print-system.jar

# ---- 数据库 ----
sudo mysql -e "CREATE DATABASE print_system DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;"
sudo mysql -e "CREATE USER 'printsys'@'localhost' IDENTIFIED BY '你的口令';"
sudo mysql -e "GRANT ALL ON print_system.* TO 'printsys'@'localhost';"
sudo mysql print_system < backend/schema-mysql.sql

# ---- 环境变量 ----
sudo cp .env.example /opt/printsys/.env && sudo chmod 600 /opt/printsys/.env
sudo vi /opt/printsys/.env

# ---- systemd ----
sudo cp deploy/printsys-backend.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now printsys-backend
journalctl -u printsys-backend -f

# ---- 前端 ----
cd ../frontend && npm ci && npm run build
sudo rm -rf /opt/printsys/frontend/dist && sudo cp -r dist /opt/printsys/frontend/dist
sudo chown -R www-data:www-data /opt/printsys/frontend/dist

# ---- Nginx ----
sudo cp ../deploy/nginx.conf /etc/nginx/conf.d/printsys.conf
sudo vi /etc/nginx/conf.d/printsys.conf          # 改域名与证书路径
sudo nginx -t && sudo systemctl reload nginx
```

首次启动日志里应能看到：

```
初始化管理员账号 admin
Tomcat started on port 8080
```

看到这两行说明环境变量与数据库都通了。

## 5. 支付渠道接入

### 5.1 支付宝当面付

1. 登录 [支付宝开放平台](https://open.alipay.com) → 创建「网页/移动应用」，拿到 **APPID**。
2. 在「开发设置 → 接口加签方式」选择 **公钥模式**，用官方工具生成 RSA2 密钥对：
   - 应用私钥 → `ALIPAY_PRIVATE_KEY`（PKCS8，单行，换行用 `\n`）
   - 上传应用公钥后，平台给出**支付宝公钥** → `ALIPAY_PUBLIC_KEY`（注意不是应用公钥）
3. 「产品中心」开通 **当面付**（`alipay.trade.precreate`）。
4. 商户 PID（2088 开头）→ `ALIPAY_SELLER_ID`。**这个必须填**，回调会校验，防止有人把自己的收款码挂进来。
5. 开放平台「开发设置 → 服务器域名/网关」里配置授权回调地址（本系统用异步通知，不需要同步跳转地址，但建议配上 `https://你的域名/user/orders`）。

`.env` 示例：

```ini
ALIPAY_ENABLED=true
ALIPAY_APP_ID=2021xxxxxxxxxxxx
ALIPAY_PRIVATE_KEY=MIIEvQIBADANBgkqhki...
ALIPAY_PUBLIC_KEY=MIIBIjANBgkqhkiG9w0...
ALIPAY_SELLER_ID=2088xxxxxxxxxxxx
```

异步通知地址由后端自动带上：`https://<PUBLIC_BASE_URL 的域名>/api/pay/notify/alipay`。

### 5.2 微信支付 APIv3 Native

1. [微信支付商户平台](https://pay.weixin.qq.com) → 产品中心 → 开通 **Native 支付**。
2. 账户中心 → API 安全 → 申请 **APIv3 密钥**（32 位）→ `WECHAT_API_V3_KEY`。
3. 申请 **API 证书**：得到 `apiclient_key.pem`（商户私钥）→ `WECHAT_PRIVATE_KEY`，以及证书序列号 → `WECHAT_MERCHANT_SERIAL_NO`。
4. 下载 **平台证书**（或使用官方 `wechatpay-java` 的 CertificateDownloader）→ `WECHAT_PLATFORM_CERTS`。
     - 多个证书用换行分隔；后端会按回调头里的 `Wechatpay-Serial` 选择对应证书验签。
     - 平台证书会轮换，**建议把下载写成定时任务**，每天刷新一次。
5. 商户号 → `WECHAT_MCH_ID`；关联的公众号/APP 的 APPID → `WECHAT_APP_ID`。

```ini
WECHAT_ENABLED=true
WECHAT_APP_ID=wx1234567890abcdef
WECHAT_MCH_ID=1600000000
WECHAT_API_V3_KEY=32位密钥
WECHAT_MERCHANT_SERIAL_NO=5157F09EFDC096DE15EBE81A47057A72...
WECHAT_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\nMIIEv...
WECHAT_PLATFORM_CERTS=-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----
```

回调地址：`https://你的域名/api/pay/notify/wechat`（下单时自动带在 `notify_url`）。

### 5.3 验证支付是否真的通了

1. 用真实账号下 0.01 元的小单（把 A4 黑白单价临时设为 0.01，最低消费 0.01）。
2. 扫码支付。
3. 管理端「订单」里看状态是否在 5 秒内变成「已支付」，随后「打印任务」出现 PENDING。
4. **反向验证**：把 `ALIPAY_SELLER_ID` 改错一位，重启，再支付——回调应被拒（订单不变），日志里有"收款方不匹配"。这一步能证明校验确实生效。

> 注意：不要把 `PAY_MOCK_ENABLED` 设为 true 上线。设为 true 时任何人（包括学生）都能把订单标记为已支付而不付钱。

## 6. 短信验证码接入

| 渠道 | 需要的参数 | 说明 |
|---|---|---|
| `aliyun` | `ALIYUN_ACCESS_KEY_ID` / `SECRET` / `SIGN_NAME` / `TEMPLATE_CODE` | 模板变量必须只有一个 `${code}` |
| `tencent` | `TENCENT_SECRET_ID` / `SECRET_KEY` / `SDK_APP_ID` / `SIGN_NAME` / `TEMPLATE_ID` | 模板变量同理 |
| `webhook` | `SMS_WEBHOOK_URL` + `SMS_WEBHOOK_TOKEN` | 自建网关：`POST {phone, code, content}`，Header `Authorization: Bearer <token>` |
| `log` | — | **仅开发**，验证码打在日志里，不真正发短信 |

限流默认值（可在 `application.yml` 调整）：同号 60 秒冷却、每小时 10 条；同 IP 每小时 30 条；验证失败 5 次作废。

## 8. 打印助手部署

### 8.1 打包

在任意装了 .NET 8 SDK 的机器上：

```bash
cd print-agent/PrintAgent

# 依赖目标机安装 .NET 8 Runtime
dotnet publish -c Release -o publish

# 或者打成免安装运行时（体积大但目标机什么都不用装）
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish-win
```

把 `publish` 目录整个拷到打印电脑（例如 `C:\PrintAgent\`）。

### 8.2 Windows 安装

以管理员身份打开 PowerShell，在 `publish` 目录执行：

```powershell
.\install-agent.ps1 `
  -ApiBaseUrl "http://192.168.1.10:8080" `
  -AgentToken "与服务器 .env 中 AGENT_TOKEN 一致" `
  -TerminalId "T01" `
  -PrinterName "HP LaserJet Pro M404-M405"
```

脚本会：

1. 检查 .NET 运行时、SumatraPDF、打印机是否存在（名称必须与系统里完全一致）
2. 生成 `agent.json`
3. 注册计划任务 `PrintSystemAgent`（开机自启，SYSTEM 账户，崩溃自动重启）
4. 跑一次 `--check` 自检

常用命令：

```powershell
Get-ScheduledTaskInfo -TaskName PrintSystemAgent     # 看上次运行结果
Restart-ScheduledTask -TaskName PrintSystemAgent     # 重启助手
Unregister-ScheduledTask -TaskName PrintSystemAgent -Confirm:$false   # 卸载
notepad C:\PrintAgent\logs\agent-$(Get-Date -Format yyyyMMdd).log     # 看日志
```

### 8.3 Linux 打印点（CUPS）

```bash
sudo apt install -y cups-client
lpstat -p -d                       # 确认打印机存在

sudo mkdir -p /opt/printsys/agent
sudo cp print-agent/PrintAgent/publish-linux/* /opt/printsys/agent/   # linux-x64 发布产物
sudo cp deploy/printsys-agent.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now printsys-agent
journalctl -u printsys-agent -f
```

`/opt/printsys/.env` 里加上：

```ini
PRINTSYS_API_BASE=http://127.0.0.1:8080
PRINTSYS_AGENT_TOKEN=<与后端一致>
PRINTSYS_TERMINAL_ID=T01
PRINTSYS_PRINTER=HP-LaserJet-M404
```

### 8.4 助手命令行

| 命令 | 用途 |
|---|---|
| `PrintAgent` | 正常运行（常驻循环） |
| `PrintAgent --check` | 只做自检：配置、后端连通、密钥、打印通道、打印机，然后退出（**现场验收必跑**） |
| `PrintAgent --once` | 只处理一条任务就退出（联调用） |
| `PrintAgent --dry-run` | 领取并下载但不真正打印，随后回传失败标记（**不浪费纸张地验证整条链路**） |

### 8.5 现场验收清单（打印点必做）

- [ ] `PrintAgent --check` 输出「后端连通正常，AgentToken 校验通过」
- [ ] `--check` 没有「未找到 SumatraPDF」警告
- [ ] `--check` 打印出的「目标打印机」就是实际那台
- [ ] 用 `--dry-run --once` 走一遍：日志里出现"领取任务 → 已下载 … KB"
- [ ] 真实打一单：份数、单双面、彩色是否符合所选
- [ ] **拔掉打印机网线再打一单**：管理端应显示「打印失败」并自动退款（验证队列回查生效）
- [ ] 关掉助手进程再打一单：任务超时后应被回收重排，助手重启后能补上

## 9. 日常运维

### 9.1 备份

必须备份两样：数据库、上传文件目录。

```bash
# 数据库（每天 2:00）
0 2 * * * mysqldump -uprintsys -p'口令' --single-transaction print_system | gzip > /backup/db-$(date +\%F).sql.gz

# 文件目录（保留 7 天，可增量）
30 2 * * * rsync -a /opt/printsys/data/uploads/ /backup/uploads/
```

恢复：先 `gunzip < db-xxx.sql.gz | mysql -uprintsys -p print_system`，再把 `uploads` 放回原位。

> 文件有保留期（默认 7 天），超过 7 天会被定时任务清理。如果业务上要求"可追溯打印内容"，把 `FILE_RETENTION_DAYS` 调大，但要注意隐私合规。

### 9.2 日志

| 日志 | 位置 | 保留 |
|---|---|---|
| 后端 | `/opt/printsys/logs/print-system.log`（按 20MB 滚动） | 14 天 |
| 助手 | `打印电脑\logs\agent-yyyyMMdd.log` | 14 天 |
| Nginx | `/var/log/nginx/printsys.{access,error}.log` | 由 logrotate 管理 |
| systemd | `journalctl -u printsys-backend` | 由 journald 管理 |

### 9.3 升级

```bash
cd /opt/printsys-src && git pull
sudo SKIP_APT=1 bash deploy/install.sh    # 只更新 jar 与前端，不动库与 .env
```

数据库结构变更时，脚本只会执行 `CREATE TABLE IF NOT EXISTS`；**新增字段需手写 `ALTER TABLE`**（本项目 v1.1 已定型，正常升级不涉及）。

### 9.4 回滚

```bash
sudo systemctl stop printsys-backend
sudo cp /opt/printsys/backend/print-system.jar.bak /opt/printsys/backend/print-system.jar
sudo systemctl start printsys-backend
# 前端同理：把上一个 dist 目录换回来
```

建议每次发布前执行 `cp print-system.jar print-system.jar.bak`。

### 9.5 关键监控指标（建议接 Zabbix/Prometheus）

| 指标 | 告警阈值 | 采集方式 |
|---|---|---|
| `/api/health` 可用性 | 连续 3 次失败 | HTTP 探针 |
| 待处理任务积压（PENDING > 5 分钟） | > 3 条 | 管理端任务页 / SQL |
| 退款失败数（当日） | > 0 | `select count(*) from refund_record where status='FAILED' and created_at>curdate()` |
| 磁盘使用率 | > 80% | 系统监控 |
| 打印失败率 | 单日 > 10% | 管理端统计 |

## 10. 故障排查

| 现象 | 排查顺序 |
|---|---|
| 扫码后订单一直是「支付中」 | ① 后端日志搜 `notify`，看有没有收到回调 ② 渠道后台看通知记录，多半是公网地址不通或证书不被信任 ③ 用 `curl -k https://域名/api/health` 从外网验证 ④ 检查 `PUBLIC_BASE_URL` 是否是 https 且无多余路径 |
| 回调收到但订单没变 | 日志搜「验签失败 / 收款方不匹配 / 金额不匹配」——这三类都会拒绝入账，是**正确行为**，按提示核对商户参数 |
| 用户已付款，但一直不出纸 | ① 管理端「打印任务」看任务是否 PENDING ② 看助手日志有没有"领取任务" ③ 检查 `TerminalId` 是否与下单页面 `?t=` 一致 ④ `PrintAgent --check` 看能否连上后端 |
| 出纸了但系统显示"打印中" | 助手没能回传结果（网络抖动），任务会在 `TASK_CLAIM_TIMEOUT_MINUTES`（默认 15 分钟）后被回收重排。若实际已出纸，请管理员在订单页点「完成」或手工关单，避免重复打印 |
| 打印张数不对（少打/多打） | SumatraPDF 是否安装；份数参数是否被驱动忽略；双面是否被驱动强制单面。用 `--check` 与试打验证 |
| 上传 Word 报"转换失败" | 服务器 `soffice --version` 是否正常；磁盘是否满；`CONVERT_ENABLED` 是否为 true |
| 上传图片报"文件类型不支持" | 魔数校验拒绝了伪装文件；确认是真正的 JPG/PNG/BMP/GIF |
| 验证码收不到 | `SMS_PROVIDER` 是否为 `log`（只打日志不发短信）；云厂商签名/模板是否审核通过；看后端日志的发送结果与错误码 |
| 管理端登录提示"用户名或口令错误" | `ADMIN_PASSWORD` 只在**首次启动、库中无该账号**时生效；已存在则不会覆盖。忘记口令时用 `UPDATE admin_user SET password_hash=NULL` 后重启重新初始化，或直接在库中删除该行 |
| 用户被封禁后还能操作 | 封禁会删该用户全部会话，前端下一次请求即 401 跳登录；若仍能操作说明请求没有带 token（检查是否有缓存或直连后端） |
| 页面 502 | 后端没起来：`journalctl -u printsys-backend -n 100`；端口冲突：`ss -lntp \| grep 8080` |
